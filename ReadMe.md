# CIFAR-10 CNN Pipeline — Git, DVC & DagsHub

An end-to-end computer vision project that trains a Convolutional Neural Network (CNN) to classify CIFAR-10 images into 10 object categories. The project is designed to make data, model artifacts, code, and experiment outputs reproducible using **Git**, **DVC**, and **DagsHub**.

**Repository:** https://dagshub.com/MuhammadNaveed9003/cifar10-cnn-pipeline

## Project Goals

- Build a CNN for CIFAR-10 image classification.
- Keep preprocessing, training, and evaluation in separate Python scripts.
- Manage configuration through `params.yaml`.
- Define and reproduce the workflow with `dvc.yaml` and `dvc repro`.
- Version datasets and model artifacts with DVC and store them in DagsHub.
- Maintain incremental Git history and demonstrate branching, diffs, stash, rebase, reset, and conflict resolution.
- Target at least **75% test accuracy**, as specified in the assignment. Actual results should be taken from the generated `metrics.json`.

## Dataset

CIFAR-10 contains 60,000 RGB images of size 32 × 32 across 10 classes:

`airplane`, `automobile`, `bird`, `cat`, `deer`, `dog`, `frog`, `horse`, `ship`, and `truck`.

It includes 50,000 training images and 10,000 test images. The preparation stage downloads/loads the dataset and stores the raw files locally for later pipeline stages.

Some data and model files may not appear directly in Git because DVC tracks their metadata in `.dvc` pointer files and stores the large artifacts in the configured remote.

## Configuration

Edit `params.yaml` to configure preprocessing and training. Depending on the implementation, parameters may include:

- `preprocess.val_size` — fraction of training data reserved for validation
- `preprocess.seed` — random seed used for the split
- `preprocess.image_size` — target image size
- `train.num_filters` — CNN filter configuration
- `train.dropout_rate` — dropout rate
- `train.learning_rate` — optimizer learning rate
- `train.epochs` — number of training epochs
- `train.batch_size` — training batch size

Use the parameter names actually defined in the repository's `params.yaml`.

## Run the Pipeline

Run all required stages in dependency order with:

```bash
dvc repro
```

The pipeline is intended to run these stages:

1. **Prepare** — load CIFAR-10 and save raw training/test data.
2. **Preprocess** — convert pixel values, apply the configured normalization/standardization, and split training data into training and validation sets.
3. **Train** — train the CNN and save the model and training history.
4. **Evaluate** — calculate test loss/accuracy, create a confusion matrix, and write `metrics.json`.

To run an individual script manually, use the corresponding command, for example:

```bash
python src/prepare.py
python src/preprocess.py
python src/train.py
python src/evaluate.py
```

Individual scripts may require their preceding stage's outputs to exist. For the full reproducible workflow, use `dvc repro`.

## DVC and DagsHub

DVC tracks large data/model artifacts while Git tracks source code, configuration, and DVC metadata. The DagsHub repository hosts the Git repository and can host the DVC remote artifacts.

Useful commands:

```bash
# Inspect configured DVC remotes
dvc remote list

# Check whether tracked data/artifacts match their metadata
dvc status

# Upload DVC artifacts to the configured remote
dvc push

# Download artifacts from the configured remote
dvc pull

# View pipeline stages and dependencies
dvc dag
```

The DVC remote must be configured for your repository and your credentials must be set up locally. Do not place credentials or tokens in `params.yaml`, `dvc.yaml`, or committed files.

Check the actual filenames in `dvc.yaml` and the scripts, because output names depend on the implementation.

## Reproducibility and Versioning

1. Commit code and configuration changes to Git in small, meaningful commits.
2. Track large datasets and model artifacts with DVC.
3. Run `dvc repro` after changing a dependency or parameter.
4. Review `dvc status` and the generated metrics.
5. Commit updated `dvc.yaml`, `params.yaml`, `dvc.lock`, metrics, and DVC pointer files when appropriate.
6. Run `dvc push` to upload artifact versions to the configured DagsHub remote.
